1.0 - 4.0: Architecture & Web Technologies

1.0 What is the MERN Stack?

The MERN Stack is a collection of technologies used together to build modern web applications. Think of MERN like a complete kitchen setup for cooking software:

  • M – MongoDB → Database (Tool for storing data)
  • E – Express.js → Server framework (Tool for requests)
  • R – React.js → Frontend (Tool for interface)
  • N – Node.js → JavaScript runtime (Runs JS on server)

🍲 The Jollof Rice Analogy:

Just like you need rice, stew, pot, and fire to cook jollof rice, you need all four MERN tools to build a full web application.

2.0 Understanding Three-Tier Architecture

1️⃣ Presentation Tier (Frontend)

What users see and interact with (HTML, CSS, React).
Example: Your POS machine screen or bank app interface.

2️⃣ Application Tier (Backend)

The middleman. Handles logic (Node.js, Express.js).
Example: A danfo conductor collecting money and telling the driver who has paid.

3️⃣ Data Tier (Database)

Stores info permanently (MongoDB, MySQL).
Example: The ledger book where the conductor records payments.

YOU (Frontend) → WAITER (Server) → CHEF (Database)

3.0 Types of Applications

  • 3.1 Website: Static. Content doesn't change (e.g., printed flyer, school info page).
  • 3.2 Web App: Dynamic. Content changes based on actions (e.g., Jumia, Facebook, NIN portal).
  • 3.3 Native App: Installed directly on OS (e.g., Opay, WhatsApp from Play Store).

4.0 Common Technologies

  • Server-Side: Node.js, PHP, Python, Java, C#.
  • Client-Side: React, HTML, CSS, Angular, Vue.
  • Databases: SQL (MySQL - like a school register table) vs NoSQL (MongoDB - like a cabinet of files).

5.0 & 6.0 Introduction to Node.js & NPM

Node.js allows JS to run outside the browser—like giving NEPA light to JavaScript at night. NPM (Node Package Manager) is used to install tools.

Step-by-Step: Initializing a Node Project

To start a backend project, you must initialize it. This creates your package.json file.

# Step 1: Create a folder and enter it
mkdir my-backend
cd my-backend

# Step 2: Initialize NPM (the -y says 'yes' to default settings)
npm init -y

7.0 Express.js & 8.0 Modules

Express is a Node.js framework used to create servers and handle requests (👉 Like a well-organized waiter that understands customer orders). In Node, we use require() (CommonJS) to import modules.

Step-by-Step: Creating Your First Express Server

# Step 1: Install Express
npm install express
// Step 2: Create a file named server.js and add this code:

const express = require('express'); // Import express
const app = express(); // Initialize the app

// Step 3: Create a basic route (When user visits home page)
app.get('/', (req, res) => {
    res.send('Welcome to my Node Backend!');
});

// Step 4: Tell the server to listen on a port
const PORT = 3000;
app.listen(PORT, () => {
    console.log(`Server is running on http://localhost:${PORT}`);
});

9.0 - 10.0: Requests, Responses & Templates

9.0 Requests and Responses

How Communication Works: Frontend sends Request → Server sends Response.
⚠️ Any request from the browser URL bar is inherently a GET request.

GET Request (Fetching Data)

Example: Viewing posts on Facebook.

app.get('/users', (req, res) => {
    // Logic to fetch users from database goes here
    res.json({ message: "Here is the list of users" });
});

POST Request (Sending Data)

Example: Creating a new account.

app.post('/users', (req, res) => {
    // req.body contains the data sent from the frontend
    const newUser = req.body; 
    res.status(201).json({ message: "User created successfully!" });
});

PUT / PATCH Request (Updating)

Example: Editing your profile. (PUT replaces whole data, PATCH partially updates).

app.put('/users/:id', (req, res) => {
    const userId = req.params.id; // Get ID from URL
    res.json({ message: `User ${userId} updated successfully` });
});

DELETE Request

Example: Deleting your account.

app.delete('/users/:id', (req, res) => {
    const userId = req.params.id;
    res.json({ message: `User ${userId} has been deleted` });
});

11.0 - 12.0: Databases, MongoDB & Mongoose

11.0 What is MongoDB?

MongoDB is a NoSQL (Non-Relational) database. Instead of tables, it uses Documents.

📂 MongoDB Structure Analogy:

  • Cluster → The Filing Cabinet
  • Database → A specific Drawer
  • Collection → A File folder
  • Document → The piece of Paper inside

12.0 Schemas, Models & Mongoose Practice

A Schema defines the exact structure of your documents (Data types, required fields). A Model represents the collection and allows you to run CRUD operations.

Step-by-Step: Creating a School Portal Schema

First: npm install mongoose

const mongoose = require('mongoose');

// Step 1: Define the Schema structure
const studentSchema = new mongoose.Schema({
    firstname: { 
        type: String, 
        required: true // Must be provided
    },
    lastname: { 
        type: String, 
        required: true 
    },
    email: { 
        type: String, 
        unique: true // No two students can have the same email
    },
    password: { 
        type: String,
        required: true
    },
    creationDate: { 
        type: Date, 
        default: Date.now // Automatically assigns current date
    }
});

// Step 2: Create the Model
// 'Student' will become 'students' in MongoDB automatically
const Student = mongoose.model('Student', studentSchema);

module.exports = Student;

13.0: MVC Architecture in Practice

Model-View-Controller (MVC) is how we organize code professionally.
👉 Analogy: Principal (Controller) managing Classrooms (Views) based on Student Records (Model).

Routes (The Pathways)

Routes direct the request to the correct Controller function. (File: studentRoutes.js)

const express = require('express');
const router = express.Router();
// Import the logic from the controller
const { registerStudent } = require('../controllers/studentController');

// When user POSTs to /register, run the registerStudent logic
router.post('/register', registerStudent);

module.exports = router;

Controller (The Logic / Principal)

Controllers contain the actual business logic. (File: studentController.js)

const Student = require('../models/studentModel');

// The logic to handle registering a student
const registerStudent = async (req, res) => {
    try {
        const { firstname, lastname, email, password } = req.body;
        
        // Save to Database using the Model
        const newStudent = await Student.create({
            firstname, lastname, email, password
        });
        
        res.status(201).json({ message: "Student registered!", data: newStudent });
    } catch (error) {
        res.status(400).json({ error: "Registration failed" });
    }
};

module.exports = { registerStudent };

Model (The Database Structure)

Just like we did in Section 12.0! (File: studentModel.js)

const mongoose = require('mongoose');

const studentSchema = new mongoose.Schema({
    firstname: String,
    lastname: String,
    email: String,
    password: String // (In real life, this must be hashed!)
});

module.exports = mongoose.model('Student', studentSchema);

14.0 - 15.0: Authentication & Security

Authentication: Confirms WHO the user is.
Authorization: Confirms WHAT the user is allowed to do.

14.3 Password Hashing (Bcrypt)

Never store raw passwords. 👉 Like turning garri into eba—you can’t go back.

// npm install bcrypt
const bcrypt = require('bcrypt');

const hashPassword = async (rawPassword) => {
    // 10 is the "salt rounds" (security level)
    const salt = await bcrypt.genSalt(10);
    const hashed = await bcrypt.hash(rawPassword, salt);
    
    // Result: $2b$10$xk92jdh728hd...
    return hashed; 
};

14.4 JWT (JSON Web Token)

Generates a secure digital "ID Card" so users stay logged in without sending their password every time.

// npm install jsonwebtoken
const jwt = require('jsonwebtoken');

const generateToken = (userId) => {
    // Create token containing the user's ID
    const token = jwt.sign(
        { id: userId }, 
        "MY_SECRET_KEY", // Keep this secret!
        { expiresIn: '1d' } // Expires in 1 day
    );
    return token;
};

Express handles HTTP requests.
Security is critical (hash passwords, use JWT).
