BACKEND: Forms, MongoDB & MVCR Architecture

A practical guide to collecting form data, storing it in MongoDB, hashing passwords, and organizing an Express application with MVCR architecture.

BACKEND

1. Introduction

In web development, users often need to submit information through forms. Examples include creating an account, registering for a course, logging in, and making online purchases.In this lesson, we will learn how to collect information from a user through an HTML form, send the information to an Express.js server, and store it in a MongoDB database.We will use the following technologies:

  • EJS: Used to create dynamic HTML pages.
  • Node.js: JavaScript runtime environment.
  • Express.js: A Node.js framework used to build web servers and handle requests.
  • MongoDB: A NoSQL database used to store information.
  • Mongoose: A library that makes interacting with MongoDB easier.
  • Bcrypt: Used to hash passwords before storing them.

2. What is EJS?

EJS stands for Embedded JavaScript Templates.It is a templating engine that allows us to write JavaScript inside HTML to create dynamic web pages.For example:

<h1>Welcome, <%= username %></h1>

If the username is David, the browser displays:

Welcome, David

Common EJS Syntax

1. Displaying a value

<%= username %>

Displays a value and escapes HTML.2. Executing JavaScript without displaying its result

<% let age = 20; %>

3. Displaying raw HTML (use cautiously)

<%- htmlContent %>

3. What is Express.js?

Express.js is a lightweight web framework built for Node.js.It helps developers create servers, manage routes, receive requests, and send responses.Example:

const express = require("express");const app = express();app.get("/", (req, res) => {

Understanding HTTP Methods

HTTP methods determine the type of action a client wants to perform.

  • GET: Used to request or retrieve information.
  • POST: Used to submit or send information.
  • PUT: Used to update information.
  • PATCH: Used to partially update information.
  • DELETE: Used to remove information.For our registration system, we will use GET to display the signup form and POST to submit the registration information.

4. Understanding HTML Forms

An HTML form is used to collect information from users.Example:

<form action="/signup" method="POST">



<input type="text" name="fullname" placeholder="Full Name">



<input type="email" name="email" placeholder="Email">



<input type="password" name="password" placeholder="Password">



<button type="submit">Register</button></form>

Important Form Attributes

  • action: Specifies where the form information will be sent.
  • method: Specifies how the information will be submitted.
  • name: Identifies each form field so the server can access its value.
  • type: Specifies the type of input expected.Important: The name attribute is very important when submitting forms because Express uses these names to identify the submitted information.

6. What is MongoDB?

MongoDB is a NoSQL database that stores information in a flexible, document-based format.Unlike traditional relational databases that use tables and rows, MongoDB stores information in collections and documents.

MongoDB Terminologies

  • Database: A container for storing related information.
  • Collection: A group of related documents.
  • Document: An individual record stored in MongoDB.
  • Field: An individual piece of information inside a document.Example of a student document:
{



fullname: "David Excel",



email: "david@gmail.com",



password: "hashed_password"}

7. What is Mongoose?

Mongoose is an Object Data Modeling (ODM) library that allows Node.js applications to interact with MongoDB.It provides schemas and models for organizing and managing database information.

What is a Schema?

A schema defines the structure of documents in a MongoDB collection.Example:

const mongoose = require("mongoose");const studentSchema = new mongoose.Schema({



fullname: String,



email: String,



password: String});

What is a Model?

A model is created from a schema and allows us to perform database operations.Example:

const Student = mongoose.model("Student", studentSchema);

We can now use the Student model to create, retrieve, update, and delete student records.

9. Understanding the Complete Process

The registration process follows these steps:1. A student opens the signup page.2. EJS displays the registration form.3. The student enters their information.4. The browser sends the information to /signup using the POST method.5. Express receives the information through req.body.6. Bcrypt hashes the password.7. Mongoose creates a new student document.8. The document is saved in MongoDB.9. Express renders the success page.

Remember:

Passwords should never be stored as plain text. Always hash passwords before saving them. Also, real applications should validate inputs on the server, protect against weak passwords, and avoid displaying sensitive information.

10. INTRODUCTION TO MVCR ARCHITECTURE

What is MVCR Architecture?MVCR stands for:M – ModelV – ViewC – ControllerR – RoutesMVCR is an application structure that helps developers organize their code into separate files and folders based on their responsibilities.Instead of writing our entire application inside one file, we divide it into different parts to make our code easier to understand, maintain, debug and scale.

Understanding the Four Components

1.

Model (M)

The Model is responsible for defining the structure of our data and interacting with the database.It contains our Mongoose schemas and models.Example:models/Student.js2.

View (V)

The View is responsible for what users see and interact with.It contains the frontend pages of our application, such as registration forms, login pages and dashboards, it is currently replacing our REACT.Example:views/signup.ejs3.

Controller (C)

The Controller contains the logic that handles requests from users.It receives information from the request, performs the necessary operations, communicates with the Model and determines the response to send back.Examples of controller responsibilities:Registering a new student.Retrieving student records.Handling login operations.Updating student information.Deleting student records.4.

Routes (R)

Routes define the different URLs and HTTP methods available in our application.They determine which controller function should handle a particular request.Examples:GET / – Display the signup page.POST /signup – Handle student registration.GET /students – Display all registered students.

10.1 Why Do We Need MVCR Architecture?

Imagine building an application with 50 different features and writing all the code inside one index.js file.The file would become very large and difficult to manage.MVCR helps us to:Organize our project into separate files.Avoid writing all application logic in one file.Make debugging easier.Reuse code and functions.Make teamwork easier.Maintain and expand applications easily.

10.2 Understanding the MVCR Workflow

When a user interacts with our application, the following process takes place:The user interacts with the View.The request is sent to the appropriate Route.The Route directs the request to a Controller.The Controller processes the request and communicates with the Model when database operations are needed.The Model interacts with MongoDB.The Controller receives the result and sends an appropriate response, often by rendering a View.
