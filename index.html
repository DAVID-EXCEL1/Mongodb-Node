1.0 - 4.0: Introduction, Node.js & Engines

1.0 Introduction to the MERN Stack

1.1 What is MERN Stack?
The MERN Stack is a popular technology stack used to build full-stack web applications using JavaScript from start to finish.

  • M – MongoDB → Database (where data is stored)
  • E – Express.js → Backend framework (server logic)
  • R – React.js → Frontend library (user interface)
  • N – Node.js → Runtime environment (runs JS outside browser)

🍽️ Think of MERN like a restaurant business:

  • React (Frontend) → The dining area customers see
  • Express + Node (Backend) → The waiter taking orders
  • MongoDB (Database) → The kitchen where food is prepared/stored

11.0: React Styling Guide (Step-by-Step)

Styling in React can be done in several ways depending on the size of your project. Here is how to write and implement them in your components.

Method 1: Inline Styling

In React, inline styles are not passed as a string. Instead, they are passed as a JavaScript Object. Because it's JavaScript, CSS properties must be written in camelCase (e.g., backgroundColor instead of background-color).

const Button = () => {
  // Step 1: Create a style object
  const buttonStyles = {
    backgroundColor: '#663399', // Notice camelCase!
    color: '#FFD700',
    padding: '10px 20px',
    borderRadius: '5px',
    border: 'none'
  };

  // Step 2: Pass it to the style attribute
  return (
    <button style={buttonStyles}>
      Click Me
    </button>
  );
};

Method 2: External CSS

This is the traditional way. You write your CSS in a separate .css file and import it directly into your component. Use className instead of class. 

/* App.css */
.card-container {
  background-color: white;
  border-radius: 8px;
  box-shadow: 0 4px 8px rgba(0,0,0,0.1);
}
// App.jsx
import './App.css'; // Step 1: Import the file

const Card = () => {
  // Step 2: Use className to apply the styles
  return <div className="card-container">Content here</div>;
};

Method 3: CSS Modules

CSS Modules fix the "global scope" problem of External CSS. By naming your file [name].module.css, React will generate unique class names so your styles never clash across components.

/* Button.module.css */
.errorBtn {
  background-color: red;
  color: white;
}

// Button.jsx
import styles from './Button.module.css'; // Import as an object

const ErrorButton = () => {
  // Access the class like an object property
  return <button className={styles.errorBtn}>Delete</button>;
};

Method 4: Utility Frameworks (Tailwind)

Instead of writing custom CSS, you use pre-existing classes directly in your JSX. This is highly recommended for modern development (it's what this note uses!).

const DashboardCard = () => {
  return (
    // Applying background, padding, rounded corners, and shadow directly via classes
    <div className="bg-gray-800 p-6 rounded-xl shadow-lg">
      <h2 className="text-xl font-bold text-white">Dashboard</h2>
    </div>
  );
};

12.0: State & Props Practice

12.1 State & 12.2 Props in Action

State is data managed *inside* the component. Props are data passed *down* to a child component. Let's see them work together.

import { useState } from 'react';

// PARENT COMPONENT
const AppDashboard = () => {
  // 1. Defining State (variables managed locally)
  const [instructorName, setInstructorName] = useState("David");
  
  return (
    <div>
      <h1>Welcome to the Cohort</h1>
      {/* 2. Passing state down as Props */}
      <ProfileCard name={instructorName} role="Lead Software Engineer" />
    </div>
  );
};

// CHILD COMPONENT
const ProfileCard = (props) => {
  // 3. Receiving Props (Read-only data)
  return (
    <div className="card">
      <h2>Hello, {props.name}</h2>
      <p>Title: {props.role}</p>
    </div>
  );
};

12.3 State Lifting (Crucial Concept)

What happens if the Child needs to change the Parent's state? Because props are read-only, the Child can't change it directly. Solution: The Parent passes a function down as a prop, and the Child calls that function. 

// PARENT COMPONENT holds the state
const CounterApp = () => {
  const [count, setCount] = useState(0);

  // Function to update state
  const incrementCount = () => {
    setCount(count + 1);
  };

  return (
    <div>
      <h1>Total Clicks: {count}</h1>
      {/* Lift State: Pass the function down to the child */}
      <ActionButton onActionClick={incrementCount} />
    </div>
  );
};

// CHILD COMPONENT just triggers the function
const ActionButton = (props) => {
  return (
    // When clicked, it fires the function belonging to the Parent
    <button onClick={props.onActionClick}>
      Add +1
    </button>
  );
};

13.0 React Hooks

Hooks are essential functions that let you "hook into" React state and lifecycle features from functional components.

useState: The Data Driver

This is how you make your components interactive by storing data that changes over time.

  • Triggers Re-renders: When you update a state variable, React automatically updates the UI to reflect the change.
  • Syntax: Returns a pair—the current state value and a function to update it.
  • Best for: Form inputs, toggle switches, or API data.
import { useState } from 'react';

const ThemeToggle = () => {
  // Practice Step 1: Initialize state
  const [isDarkMode, setIsDarkMode] = useState(true);

  // Practice Step 2: Create a toggle function
  const handleToggle = () => {
    setIsDarkMode(!isDarkMode); // Flips true to false, and vice versa
  };

  // Practice Step 3: Use state to drive the UI
  return (
    <div style={{ background: isDarkMode ? '#111827' : '#FFFFFF' }}>
      <p>Current Theme: {isDarkMode ? 'Dark' : 'Light'}</p>
      <button onClick={handleToggle}>Change Theme</button>
    </div>
  );
};

useEffect: The Side-Effect Manager

Handles anything that happens "outside" of the normal render cycle (API calls, changing document title, timers).

[] (Empty Array):
Runs only ONCE after the first render. (Best for fetching initial data).
[value]:
Runs whenever 'value' changes. 
import { useState, useEffect } from 'react';

const UserList = () => {
  const [users, setUsers] = useState([]);

  // Practice: Fetch data when component loads
  useEffect(() => {
    // 1. Fetch logic
    fetch('https://api.example.com/users')
      .then(response => response.json())
      .then(data => setUsers(data));
      
    // 2. Optional Cleanup (like stopping a setInterval)
    return () => {
      console.log("Component destroyed");
    };
  }, []); // <-- Empty array ensures this only fetches ONCE

  return <div>Loaded {users.length} users.</div>;
};

useRef: The "Secret" Storage

Like a "box" that holds a value but doesn't tell React to re-render when the value inside changes.

  • Direct DOM Access: Primarily used to grab a physical HTML element (like focusing an input field manually).
  • Performance: Great for storing IDs for timers without causing extra UI updates.
import { useRef } from 'react';

const FocusForm = () => {
  // Practice Step 1: Create a reference
  const inputRef = useRef(null);

  const focusInput = () => {
    // Practice Step 3: Access the actual HTML DOM node
    inputRef.current.focus(); 
  };

  return (
    <div>
      {/* Practice Step 2: Attach the ref to the element */}
      <input ref={inputRef} type="text" placeholder="Type here..." />
      <button onClick={focusInput}>Click to Focus Input</button>
    </div>
  );
};
